# Ghost AI API

FastAPI service for Ghost AI. This is the only component that touches Postgres
and the only one that makes authorization decisions.

## Why this is Python

The Next.js app in `../frontend` renders UI and holds the Clerk session. Everything
else — validation, roles, database access — lives here. Prisma is
TypeScript-only, so the data layer is SQLAlchemy 2.0 async with Alembic.

## Layout

| Path | Purpose |
|---|---|
| `app/main.py` | App factory, CORS, exception handlers, `/health` and `/ready` |
| `app/config.py` | Settings from environment, via pydantic-settings |
| `app/db.py` | Async engine and session factory |
| `app/models.py` | SQLAlchemy models; the schema's source of truth |
| `app/schemas.py` | Pydantic request/response models; the API contract |
| `app/auth.py` | Clerk session JWT verification and profile lookup |
| `app/deps.py` | FastAPI dependencies: current user, role gates, rate limiting |
| `app/ratelimit.py` | Fixed-window counters in Postgres |
| `app/routers/` | One module per resource group |
| `migrations/` | Alembic environment and revisions |
| `tests/` | Unit tests that need no database |

## Setup

```bash
uv venv
uv pip install -e ".[dev]"
cp .env.example .env      # then fill it in
```

You need a Postgres database and a Clerk application. The minimum to boot:

```
DATABASE_URL=postgresql+asyncpg://user:pass@host:5432/ghost
CLERK_SECRET_KEY=sk_test_...
```

`CLERK_JWKS_URL` is optional; it defaults to Clerk's shared JWKS endpoint. Set
it if your Clerk instance exposes keys elsewhere.

### Project invites

Invitation emails are sent through Resend. Configure `RESEND_API_KEY` and
`RESEND_FROM_EMAIL` in `backend/.env` using an address from a verified sending
domain in Resend. Set `FRONTEND_URL` to the deployed app URL outside local
development. The API reports clearly when the invite was saved but email
delivery was not configured or was rejected.

For an email address with no account yet, the recipient must sign in or sign up
using that same address to be added automatically. An address that already
belongs to a user is added as a member immediately. Resend account setup,
sender-domain verification, and DNS configuration must be completed in Resend
before real invitations can be delivered.

### AI provider

To enable AI features through OpenRouter, set `OPENROUTER_API_KEY` and
optionally `OPENROUTER_MODEL` in `.env`. The default model is
`openai/gpt-4o-mini`. `OPENROUTER_HTTP_REFERER` defaults to
`http://localhost:3000` and can be set to your deployed app URL. OpenRouter is
selected ahead of direct OpenAI or Anthropic keys if more than one provider key
is configured. The AI chat panel loads the available OpenRouter models so you
can choose a model per message or compare up to three models on the same prompt.
Each selected model is a separate provider request and may use additional
OpenRouter credits.

The configured AI provider can generate architecture diagrams or ERDs. ERD entities
include typed fields and PK/FK markers; relationship labels carry cardinality.
Generated diagrams are validated before they are applied to the canvas.

## Migrations

```bash
alembic upgrade head          # apply
alembic revision --autogenerate -m "..."   # after changing models.py
alembic downgrade -1          # roll back one
```

`alembic.ini` deliberately leaves `sqlalchemy.url` blank: `migrations/env.py`
reads `DATABASE_URL` from settings so the connection string has a single source
of truth and never lands in the repo.

The first revision, `0001_initial`, is hand-written rather than autogenerated so
it is reviewable and reproducible without a live database. Review generated
revisions before committing them.

## Running

```bash
uvicorn app.main:app --reload --port 8000
```

Interactive API docs are at `http://localhost:8000/docs`, disabled in production
by `ENVIRONMENT=production`.

## Tests

```bash
pytest
```

Unit tests only, no database needed.

For the integration tests:

```bash
export TEST_DATABASE_URL=postgresql+asyncpg://ghost:ghost@localhost:55432/ghost_test
pytest
```

They skip automatically when that variable is unset. That guard is deliberate:
silently falling back to `DATABASE_URL` is how integration tests end up
truncating a real database.

The suite covers role ranking, request validation, Clerk JWT verification,
project CRUD, role gates, the invite lifecycle, cascade deletes, and rate
limiting. The schema is built by running the real migrations in a subprocess,
not `metadata.create_all`, so the migrations themselves are covered.

## Calling it from the frontend

Clerk issues a session JWT that this service verifies directly, so every request
needs `Authorization: Bearer <session token>`:

```bash
curl http://localhost:8000/v1/projects \
  -H "Authorization: Bearer $CLERK_SESSION_TOKEN"
```

Set `CORS_ORIGINS` to a comma-separated allowlist of browser origins. Default is
`http://localhost:3000`.

## Authorization model

`OWNER` > `EDITOR` > `VIEWER`. Route signatures use the annotated gates from
`app/deps.py`:

```python
async def create_invite(payload: InviteCreate, project: ProjectOwner): ...
async def create_snapshot(payload: SnapshotCreate, project: ProjectEditor): ...
```

Use `Annotated` gates rather than `Depends(RoleGate(...))`. FastAPI rejects a
dependency declared in both `Annotated` and a default value, and the annotated
form keeps parameters free of Python-level defaults.

`RoleGate` returns the `Project` alone, **not** `(project, role)`. FastAPI
injects whatever the dependency returns without checking its annotation, so
returning a tuple here hands every route a tuple while `ProjectOwner` still
claims it is a `Project`.

Non-members get **404**, not 403, so project ids cannot be enumerated.

## Rate limiting

`app/ratelimit.py` implements fixed-window counters in Postgres, one row per
`(scope, subject)` in `rate_limit_bucket`. The increment and the decision are a
single statement:

```sql
INSERT INTO rate_limit_bucket (key, window_start, count) VALUES (...)
ON CONFLICT (key) DO UPDATE SET count = count + 1 RETURNING count
```

That atomicity matters: a read-then-write would let two concurrent requests both
observe "under the limit" and both be admitted. `test_ratelimit.py` covers it.

Configured in `LIMITS`, applied via `deps.enforce(scope, session, user)`:

| Scope | Limit | Window |
|---|---|---|
| `ai:generate` | 20 | 1 hour |
| `ai:spec` | 20 | 1 hour |
| `project:create` | 30 | 1 hour |
| `project:invite` | 50 | 1 hour |
| `snapshot:create` | 120 | 1 hour |

### Why per user and not per IP

Every budget is keyed on the user id. IP-based limiting is the wrong tool here:

- Two people behind one office or carrier NAT share an IP, so an IP budget lets
  one person exhaust everyone's quota.
- IP is cheap to rotate, so it under-counts deliberate abuse.
- On a cost-bearing endpoint, IP lockout is a denial-of-service lever. Anyone
  who knows a victim's IP can lock that specific person out indefinitely without
  ever touching their account.

IP limiting still makes sense on unauthenticated endpoints where there is no
user id to key on. This service has none.

### Why Postgres and not Redis

Redis is the usual answer, and would be the right one at higher volume. It would
also add a deployment, a failure mode, and a second source of truth for the AI
spend this is bounding. A single indexed upsert is comfortably fast at these
volumes. If it stops being, `app/ratelimit.py` is the only file that changes.

Note the AI endpoints have a **separate** in-flight cap (3 queued or running
tasks per project per type) that is not a rate limit. A user with plenty of
budget still gets refused when they have too much work outstanding. The two
guards return 429 with different messages.

## Notes for contributors

- `deps.current_user` upserts the user on first request. That makes it a
  fallback for the Clerk webhook, so a missed webhook delays rather than breaks.
- Pending `project_invite` rows are redeemed in the same transaction. Removing
  that call will silently break invites for users who have not signed up yet.
- `snapshot.py` talks to the Vercel Blob REST API directly instead of taking a
  dependency. If you change that, keep the 4MB payload cap in `schemas.py` in
  step.
- Error bodies are normalised to `{"error": "..."}` in `main.py`, with
  validation errors keeping a structured `detail` list. Do not raise bare
  `HTTPException` expecting a `detail` key to reach the client unchanged.
- Alembic enums are declared with `create_type=False`. Without it SQLAlchemy
  emits a second `CREATE TYPE` when building the first table that uses one and
  the migration fails with `type "role" already exists`.
- `user` is a Postgres reserved word. Quote it in raw SQL; SQLAlchemy quotes it
  for you.
